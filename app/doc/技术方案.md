# 钉钉知识库文件上传服务 - 技术方案

## Context

OA 系统每天/每周定时将失效分析流程中产生的 PDF 报告上传到钉钉知识库，按日期归档。
本服务作为中间桥梁：接收 OA 推送的文件，调用钉钉 API 完成上传。

---

## 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | FastAPI | 异步、自动文档、高性能 |
| HTTP 客户端 | httpx | 支持异步，可上传大文件流式传输 |
| 配置管理 | pydantic-settings + .env | 类型安全、环境变量隔离敏感信息 |
| 日志 | loguru | 开箱即用、自动轮转 |
| 定时任务 | APScheduler（可选） | token 刷新、失败重试 |
| 部署 | 待定（代码层面兼容） | 先不耦合部署方式 |

## 核心模块设计

### 1. 配置管理 (config.py)

```python
# .env 文件存放敏感信息，不入版本库
DINGTALK_APP_KEY=dingq1bpu9475vnsckra
DINGTALK_APP_SECRET=xxx
DINGTALK_SPACE_ID=xxx              # 目标知识库 ID
DINGTALK_ROOT_DENTRY_UUID=xxx      # 知识库根目录 UUID
DINGTALK_ADMIN_UNION_ID=xxx        # 管理员 unionId
API_KEY=xxx                        # OA 调用时的鉴权 key（简单 API Key 认证）
```

### 2. Token 管理 (services/token.py)

- 启动时获取 access_token，缓存到内存
- 有效期 2 小时，提前 10 分钟自动刷新（APScheduler 定时任务）
- 提供一个 `get_token()` 方法给其他模块调用

```
启动 → 请求 access_token → 缓存
                         ↓
              APScheduler 每 110 分钟刷新一次
```

### 3. 文件夹管理 (services/folder.py)

维护一个内存缓存 `{ "2026-05": "dentryUuid_xxx" }`：

```
ensure_date_folder(date_str)
    │
    ├─ 缓存命中 → 直接返回 dentryUuid
    │
    └─ 缓存未命中
         ├─ 调「获取节点列表」查找该文件夹
         ├─ 找到 → 缓存并返回
         └─ 未找到 → 调「创建知识库文档」创建文件夹 → 缓存并返回
```

文件夹命名规则：`2026-05`（按月），可配置为 `2026-05-27`（按天）。

### 4. 钉钉三步上传 (services/dingtalk.py)

```python
async def upload_file(file_bytes, file_name, parent_dentry_uuid, union_id, token):
    # Step 1: 获取上传信息
    upload_info = await get_upload_info(parent_dentry_uuid, union_id, token)
    upload_key = upload_info["uploadKey"]
    resource_url = upload_info["headerSignatureInfo"]["resourceUrls"][0]
    headers = upload_info["headerSignatureInfo"]["headers"]

    # Step 2: PUT 文件到 OSS
    await upload_to_oss(resource_url, headers, file_bytes)

    # Step 3: 提交文件
    result = await commit_file(parent_dentry_uuid, union_id, token, upload_key, file_name, len(file_bytes))
    return result
```

### 5. 对外接口 (routers/upload.py)

**接口 1：文件流直传**
```
POST /api/upload/file
Content-Type: multipart/form-data
Header: X-API-Key: xxx

参数:
  file: PDF 文件 (必填)
  date: 日期字符串 "2026-05-27" (可选，默认当天)
  name: 自定义文件名 (可选，默认用上传文件名)

响应:
  { "success": true, "dentry_uuid": "xxx", "folder": "2026-05", "file_name": "报告.pdf" }
```

**接口 2：URL 下载上传**
```
POST /api/upload/url
Content-Type: application/json
Header: X-API-Key: xxx

Body:
  {
    "file_url": "http://oa-server/reports/xxx.pdf",
    "file_name": "失效分析报告.pdf",
    "date": "2026-05-27"
  }

响应:
  { "success": true, "dentry_uuid": "xxx", "folder": "2026-05", "file_name": "失效分析报告.pdf" }
```

**健康检查**
```
GET /api/health
响应: { "status": "ok", "token_valid": true }
```

## 钉钉 API 调用清单

| 步骤 | 钉钉接口 | 方法 |
|------|---------|------|
| Token | `/gettoken` | GET |
| 获取节点列表 | `/v1.0/doc/spaces/{spaceId}/nodes` | GET |
| 创建文件夹 | `/v1.0/doc/spaces/{spaceId}/nodes` | POST |
| 获取上传信息 | `/v1.0/doc/spaces/{parentDentryUuid}/files/uploadInfos` | POST |
| 上传到 OSS | `{resourceUrl}` (阿里云) | PUT |
| 提交文件 | `/v1.0/doc/spaces/{parentDentryUuid}/files` | POST |

---

## 错误处理策略

| 场景 | 处理方式 |
|------|---------|
| Token 过期 | 自动刷新重试一次 |
| 文件夹已存在 | 忽略创建，直接使用 |
| OSS 上传失败 | 返回错误，由 OA 重试 |
| 文件名冲突 | `AUTO_RENAME` 自动重命名 |
| OA 推送大文件 | 流式读取，限制最大 100MB |

## 实现顺序

1. **项目骨架**：目录结构 + config + main.py + requirements.txt
2. **Token 管理**：获取 + 缓存 + 自动刷新
3. **三步上传核心**：获取上传信息 → OSS 上传 → 提交文件
4. **文件夹管理**：日期目录检查与创建
5. **对外接口**：文件流上传接口 + URL上传接口
6. **错误处理 + 日志**：统一异常处理、日志记录
7. **.env.example + README**
